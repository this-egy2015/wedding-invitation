# Admin tunggal dan akses petugas tamu

Pemilik menetapkan email admin melalui chat dan mengonfirmasi bahwa email tambahan adalah petugas pengelola tamu; undangan publik tetap terbuka tanpa login. Alamat admin disimpan dalam ADMIN_EMAIL privat di .env.local serta Secret Production Vercel, tidak ditulis ke repo publik. Branch codex/guest-staff-access.

Tabel invitation_staff menyimpan pasangan invitation_id/email ternormalisasi, primary key gabungan, index email, FK cascade dan CHECK normalisasi. Skema diubah hanya di src/db/schema.ts; migration 0001_thankful_mordo.sql + snapshot/journal dihasilkan db:generate. Migrasi lokal dan Turso sudah diterapkan. Snapshot konsisten Turso sebelum migrasi disimpan privat di data/backups; jumlah seluruh data aplikasi lama dan FK diperiksa setelah migrasi. Tidak membuat petugas contoh di produksi.

requireUser memanggil Supabase getUser dan mensyaratkan email terkonfirmasi serta izin admin/petugas dari DB. requireAdmin memakai email admin terkonfigurasi, tidak memakai user_metadata. getOwnedInvitation tetap memeriksa owner_id dan sekarang admin saja, melindungi editor, preview, publish, delete dan upload musik. Create invitation juga admin saja. Operasi daftar/detail/tambah/edit/hapus tamu dan moderasi ucapan memakai getGuestManagementInvitation yang memanggil requireUser lalu memeriksa penugasan per undangan. Helper listGuests/getGuest juga memeriksa akses sendiri. Revokasi tidak mengandalkan cookie/claim lama dan berlaku request berikutnya.

Admin membuka Akses Petugas dari halaman tamu; tambah email idempotent dan dinormalisasi, cabut akses tidak menghapus akun Auth maupun data tamu. Izin untuk email yang belum punya akun Supabase diperbolehkan; akun dibuat lewat permintaan magic link setelah email lolos allowlist. Tidak mengirim email ketika admin menambahkan izin. Login email di luar daftar ditolak sebelum signInWithOtp. Akun yang dibuat langsung melalui Supabase tetap ditolak aplikasi bila tidak diberi izin.

Callback sukses menuju /dashboard. Satu undangan langsung ke halaman Tambah Tamu, beberapa undangan memilih halaman pengelolaan tamu. Tidak melewati cover publik. Header petugas tidak menampilkan editor/akses admin; menebak URL atau replay action tetap ditolak server. Link publik dan RSVP tidak diubah.

Validasi: typecheck, 27 unit test dan build lulus. Tes database memakai migrasi nyata: normalisasi/duplikasi, batas per undangan, ownership lama bukan izin otomatis, FK/cascade, cabut satu dari beberapa izin, allowlist kosong, dan admin tepat email. Smoke Chrome lokal memakai tiga akun Auth sementara dan dua undangan: admin tambah/duplikasi/cabut email lewat UI; outsider ditolak di dashboard dan form login; petugas langsung ke form tamu, tambah/edit tamu berhasil; lintas undangan, editor, preview, halaman baru, pengaturan petugas dan replay action grant/edit admin ditolak; beberapa izin menampilkan pilihan; sesi lama tidak dapat menambah tamu setelah dicabut. Publik tetap 200. Fixture akun/undangan/tamu/izin dibersihkan. Skrip sementara /tmp/wedding-staff-smoke.mjs.

Belum diverifikasi: pengiriman magic link dan callback dari email hosted, serta custom SMTP. Pemilik sudah ditanya status SMTP; jangan menyatakan pengiriman email produksi siap tanpa bukti. [SMTP bawaan Supabase hanya mengirim ke anggota tim proyek](https://supabase.com/docs/guides/auth/auth-smtp), sehingga petugas di luar tim memerlukan custom SMTP. Pastikan Confirm Email hosted aktif dan Site URL/Redirect URL benar. Tidak mengirim email ke alamat nyata selama pengerjaan.
